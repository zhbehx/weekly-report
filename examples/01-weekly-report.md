# 案例：一份流水账周报怎么改成汇报

## 用户原始流水账

```
本周：
- 负责注册流程的改版，跟进了开发进度
- 参与了三次评审会
- 配合测试做了两轮回归
- 对接了数据团队，沟通了埋点需求
- 推进了会员体系的需求梳理
- 优化了首页的文案
- 加班到很晚，把上线时间保住了
```

脚本结果：

```
$ python scripts/check_report.py raw.md

结论在前 3 行：否
条目数        ：7（无数字 7 条）
弱动词开头    ：7 条
风险条        ：0（缺方案与请求 0 条）
篇幅          ：8 行
评分          ：30/100

必须改：
  - 前 3 行没有结论句（要写清：进度 / 指标 / 风险 / 需要什么决定）
  - 7 条成果没有数字
```

诊断：**这 7 条里，只有第 1 条和第 4 条产生了可验证的产出，其余全是过程。** 而过程项只有在产生结论时才值得写。

## 三栏归类

| 原句 | 归类 | 处理 |
| --- | --- | --- |
| 负责注册流程的改版，跟进了开发进度 | 成果 | 补指标：转化率变化 + 上线时间 |
| 参与了三次评审会 | 过程 | 只写结论：评审定了什么、砍了什么 |
| 配合测试做了两轮回归 | 过程 | 只写结论：缺陷数从 X 到 Y |
| 对接了数据团队，沟通了埋点需求 | 成果 | 补：几个埋点、覆盖什么、上线后能看什么 |
| 推进了会员体系的需求梳理 | 成果（未完成） | 写成「已完成 X，待 Y 决策」 |
| 优化了首页的文案 | 成果 | 补：点击率/停留时长变化 |
| 加班到很晚，把上线时间保住了 | 过程（且不可核验） | 删掉。如果要表达抗压，写「在 X 天内完成了 Y」 |

## 改写后的周报

```markdown
# 一句话状态
注册改版已上线，注册完成率 3.1% → 4.6%；首页改版排期受供应商影响可能延 3 天，
我建议先上文案版本、视觉版本下周跟上，需要你今天确认。

# 本周成果

1. **注册流程改版上线**：把 5 步压到 2 步，注册完成率 3.1% → 4.6%（口径：注册完成 / 进入注册页，剔除重复提交），按当前流量估算月增注册 6,800。
2. **埋点体系补齐**：新增 23 个埋点，覆盖注册、首页、会员三个模块，下周起可出日级漏斗。
3. **会员体系需求梳理完成 80%**：已完成权益与定价两节，剩余「积分是否叠加」需你定，我的建议是不叠加（否则财务口径要重算）。

# 风险与方案

| 风险 | 影响 | 我的方案 | 需要你决定 |
| --- | --- | --- | --- |
| 供应商视觉素材延 3 天 | 首页视觉版本 11/6 → 11/9，错过首周活动窗口 | 先上文案版本（已可用），视觉版本下周跟进 | 是否接受拆两次发，最晚今天 18:00 |

# 下周计划

1. 会员体系定稿并评审 — 11/5 前交付评审稿
2. 漏斗看板上线 — 11/7 前交付日级报表
3. 注册流程第二轮实验 — 11/8 前交付实验方案

# 其他进展

评审会确定砍掉「邀请返现」；两轮回归缺陷 14 → 2 个，均已修复。
```

## 改写后重跑

```
$ python scripts/check_report.py report.md

结论在前 3 行：是
条目数        ：6（无数字 0 条）
弱动词开头    ：0 条
风险条        ：1（缺方案与请求 0 条）
篇幅          ：16 行
评分          ：100/100
```

## 这个案例做对了什么

1. **7 条过程压缩成 3 条成果**，剩下的过程项变成「其他进展」一句话。
2. 每条成果都有**口径**（剔除重复提交），领导不用再问。
3. 风险表里有「我的方案」和「最晚何时」，领导只需选，不用想。
4. 未完成的事写成「完成 80%，剩 X 需你定」，而不是「推进中」。
5. 删掉了「加班到很晚」——努力不是成果，交付才是。
