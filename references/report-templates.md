# 五套汇报模板

## 一、周报（一屏，最常用）

```
一句话状态：（进度 + 指标 + 风险 + 请求）

本周成果（≤3 条，按影响排序）
1. 做了什么 → 影响到什么（数字）→ 下一步
2. …
3. …

风险与方案（有则写，无则删掉这一节，不要写"本周无风险"）
| 风险 | 影响 | 我的方案 | 需要你决定 |

下周计划（≤3 条，带交付物与日期）
1. {事项} — {日期} 前交付 {具体产物}

其他进展
一行带过，逗号分隔。
```

**判断标准**：直属上级 30 秒内能回答「要不要找你聊一次」。答不出来就是没写好。

## 二、月报（两屏）

```
一句话状态

一、目标达成（表格优先）
| 目标 | 目标值 | 实际 | 达成率 | 说明 |
达成率低于 80% 的必须有一句原因，高于 120% 的必须有一句可复用做法。

二、关键动作（≤3 条，每条一句因果）
因为做了 A，所以 B 从 X 到 Y。

三、下月计划（≤3 条，每条带一个可验收的指标）

四、需要的支持（只写真正卡住的，≤2 条）
```

**月报与周报的差别**：周报讲"做了什么"，月报讲"达成了什么"。不要把周报拼起来当月报。

## 三、项目汇报（一屏 + 表）

```
一句话状态（项目名 / 进度 / 偏差 / 请求）

里程碑
| 阶段 | 计划完成 | 实际/预计 | 状态 |
状态只用三个词：正常 / 有风险 / 已延期。

偏差说明（只解释"有风险"和"已延期"的）
偏差 → 原因（客观事实，不评价人）→ 影响 → 补救方案与新的时间点

决策请求（这一段决定会议效率）
需要决定的事项 / 备选方案 A B / 各自代价 / 我的建议 / 最晚决策时间
```

**关键**：决策请求必须写"最晚什么时候要定"，否则会一直悬着。

## 四、复盘（两屏）

```
一、目标 vs 结果（先摆事实，不解释）
| 维度 | 目标 | 实际 | 差距 |

二、归因（分三类，别混在一起）
- 判断问题：当初假设错在哪
- 执行问题：哪一步没做到
- 外部问题：不可控因素（放最后，且不超一条）

三、可复用结论（最重要的部分）
写"下次遇到 X，我们做 Y"，而不是"下次要更谨慎"。

四、要改的机制（≤3 条，带责任人与生效时间）
```

**最常见的失败复盘**：全篇归因于外部，结论是"加强沟通"。这种复盘写十次也不会有变化。

## 五、述职（5 页 PPT 结构）

```
P1 一句话定位：我是谁 + 我最强的一件事（带数字）
P2 业绩：目标 vs 实际（表格/柱状图），只留 3 个关键指标
P3 关键战役：1–2 个项目的判断过程（不是过程流水，是"当时怎么选"）
P4 能力对齐：对照职级要求逐条给证据（这是评委真正在看的东西）
P5 下一年规划：3 个目标，每个带可验收指标与时间点
```

**述职的评分逻辑**：评委不是在评估你的努力，是在判断「你能不能拿到下一级」。所以 P4 必须**一栏一栏对着职级要求写**，缺哪条就主动说缺、并给补的计划。

## 结论页的 6 种写法

| 场景 | 句式 |
| --- | --- |
| 正常推进 | 「{项目}按计划推进，进度 {X}%，{指标}已达 {值}，本周无阻塞。」 |
| 有风险 | 「{项目}进度 {X}%，{风险} 可能导致延期 {N} 天。我的方案是 {A}，代价是 {B}。需要你确认。」 |
| 需要资源 | 「要按期上线，还缺 {具体资源}。没有的话建议砍掉 {功能}，我倾向后者。」 |
| 结果超预期 | 「{指标} 从 {A} 到 {B}（目标 {C}）。多做对的一件事是 {具体动作}，建议推广到 {范围}。」 |
| 结果不及预期 | 「{指标} 只到 {A}（目标 {B}）。原因是我早期判断 {错误假设}，已改为 {新做法}，预计 {日期} 追回 {差距}。」 |
| 需要拍板 | 「A/B 两个方案，A 快但 {代价}，B 稳但 {代价}。我建议 {X}，最晚 {日期} 要定。」 |
